# S01 單篇記事本擷取

## Mei 版媽已結團週報

登入 LINE 後，在專案根目錄執行。預設含台北時間今天在內的最近 7 天，按發文日篩選。

```sh
.venv/bin/python -m notesync capture-week
.venv/bin/python -m notesync capture-week --from 2026-11-03 --to 2026-11-09
```

群組預設讀取 `local-evidence/line-chat.txt`，也可以加 `--chat 'LINE 群組完整名稱'`。
有明確結團時間的貼文，到達時間後才展開留言。只寫日期時，截止點是台北時間隔天零時。
`11:30 PM` 會讀為 23:30；「晚上 12 點」或無法完整辨識的時刻需先核對。
掃描只用與留言圖示相鄰的發文日期劃分貼文，正文中的日期不會結束掃描。
若有疑似未辨識到的頁尾，週報會停止，避免把相鄰貼文的內容和留言混在一起。
作者、商品或截止日讀不到時會提示核對。截止日留空會略過；未到期的貼文只在總覽標註，
留言不展開。需要人工核對時可輸入 `:q` 取消整次匯出。

指令會輸出一份本機 Excel，含週報總覽及各商品頁。明確的 `A+1 B+2` 會各自加總，
同一篇有多個品項時會額外分頁。同名買家的明確喊單加總；截斷的暱稱或多品項中未指定品項的喊單
先核對，留白的列不計入確認數量。擷取不完整的貼文只在總覽列狀態。
例如 `AB各1` 或 `A再加一個，共兩個`，請依原留言核對後輸入 `A+1 B+1` 或 `A+1（共2）`。
執行時保持 LINE 視窗在前景；原始擷取與預設 Excel 都寫入 Git 忽略的 `local-evidence/`。
可用 `--output` 指定尚未存在的本機 Excel 路徑。

週報會把已擷取、暱稱與數量均已確認，且只有 A、B 兩款的系列整理進同檔的「包書明細」。系列總表保留供核對，結團前或有待核對留言的系列留在原週報。若沒有符合條件的系列，匯出結果的 `website_import` 會顯示 0 件。網站預覽會將這張表視為待核對草稿，可在後台補團價、成本及買家對應。

舊週報可用 `notesync weekly-export <原週報.xlsx> --series <系列名稱> --output <新檔.xlsx>` 補上匯入工作表。這個命令會逐暱稱比對 A、B 明細和系列總表，並核對週報總覽的件數。

## 指定貼文名稱，自動擷取 Excel

LINE 登入後，在專案根目錄執行：

```sh
.venv/bin/python -m notesync capture-note --chat 'LINE 群組完整名稱' --post '貼文名稱'
```

可將群組的完整名稱另存為 `local-evidence/line-chat.txt`，之後只填 `--post`。
指令會搜尋貼文、自動展開並捲動留言。辨識或數量有疑問時，依終端機提示核對。
同名搜尋結果有多篇時，請用更完整的名稱。畫面遮擋、重疊或留言數無法確認時，會停止輸出。
執行時保持記事本視窗在前景並避免同時操作滑鼠。Excel 存在指令回傳的本機路徑。

## 自動開啟指定群組的記事本

先解鎖 Mac。到「系統設定 → 隱私權與安全性」允許執行指令的終端機使用「輔助使用」。
需要輸出 Excel 時也要開啟「螢幕與系統音訊錄製」權限。
在專案根目錄先測試導覽，將群組完整名稱換成 LINE 顯示的名稱。

```sh
.venv/bin/python -m notesync capture-note --chat 'LINE 群組完整名稱' --open-only
```

指令會開啟 LINE 並使用現有登入狀態。若 LINE 提供「自動登入」，可在 LINE 的登入畫面勾選。
若 LINE 要求重新登入或手機驗證，請在 LINE 完成驗證後重跑。
若記事本已開啟，請先關閉小視窗，讓程式辨識這次新開啟的視窗。

要擷取並產出 Excel，移除 `--open-only`。記事本開啟後，依提示選擇貼文、核對主題及留言總數、
展開並捲動留言，最後核對暱稱和正文。檔案會寫到 `local-evidence/line-note-*/結果/`。
自動導覽遇到介面無法辨識時，可手動開啟記事本後執行下方的 `--auto`。

## 本機截圖辨識

從專案根目錄執行以下指令。需要已安裝的 Python 環境、Xcode Command Line Tools，
以及 macOS「隱私權與安全性 → 螢幕錄製」中授權執行指令的終端機。

```sh
.venv/bin/python -m notesync capture-note --auto --author '測試作者'
```

1. 可以先啟動指令，再開啟 LINE。開啟要擷取的記事本視窗，讓貼文作者及完整主題在上半部可見。
2. 依終端機提示按 Enter，選擇辨識出的主題或輸入原文，再填 LINE 當時顯示的留言總數。
   可選用 `--subject` 限定同一篇貼文。指定的作者或主題讀不到時，指令停止。
3. 展開留言並載入較早留言，從第一則開始。按 Enter 後在 LINE 緩慢向下捲動，
   相鄰畫面保留至少兩則完整且可區分的留言。程式會自動取圖，無需操作截圖工具。
   如果重疊留言的暱稱辨識不同，請多保留幾則留言，讓兩張圖有至少兩則辨識一致的留言。
   程式會提示核對可對齊的差異。找不到唯一的重疊範圍時，需回捲再取圖。
4. 辨識筆數相符後，終端機會列出暱稱和正文。可輸入序號修正辨識錯字，再按 Enter 輸出。

原始截圖與結果都在 Git 忽略的 `local-evidence/`。輸出同一批的 UTF-8 文字檔及
Excel `.xlsx`。每個主題一個分頁，主題只顯示在最上方，表格只有暱稱和數量。
明確喊單會依暱稱加總。同一暱稱先喊 `C+1`，再喊 `C+1（共2）` 時，Excel 會顯示 2。
括號的數量會與該商品前面的喊單核對，累計不符時留空供核對。
文字檔保留完整正文。Google 試算表可用「檔案 → 匯入」匯入該 Excel。

取圖在選定的 LINE 視窗內執行。操作者控制捲動和單篇範圍。若重疊、辨識列數或留言顯示
不一致，需回捲核對或重新擷取。分頁可能被 LINE 版本、介面語言、裁切或圖片留言影響。
此指令只產生本機核對檔。Google 試算表上傳是另一步。

## 輔助使用介面探針

本機分支已提供 macOS LINE 的唯讀擷取指令。在 macOS 27.0、LINE 26.6.0 的展開留言
案例中，畫面可見作者和正文，輔助使用介面未提供可讀的留言。

## 先擷取一個畫面

在專案根目錄使用 Python 3.12 以上及 Xcode Command Line Tools。由你登入 Mac LINE，
開啟一篇有權讀取的記事本並展開留言區。若系統要求授權，在「系統設定 → 隱私權與安全性
→ 輔助使用」允許執行指令的終端機。

```sh
python3.12 -m venv .venv
.venv/bin/python -m pip install -e .
.venv/bin/python -m notesync capture-line --list-windows
.venv/bin/python -m notesync capture-line --window 1
```

將 `1` 換成清單中記事本所在視窗的編號。重新開關視窗後請重新列出編號。
已知來源時可加 `--kind line_group_note` 或 `--kind line_openchat_note`，
並用 `--scope-key`、`--note-key` 指定本機代號。同一群與同一篇沿用各自的代號。
可由你手動捲動到下一段、等待畫面更新後再擷取。每次各存一份，重疊畫面要逐筆比對。

探針讀取 Mac LINE 對 macOS 輔助使用介面公開的視窗元素和文字。結果也可能含按鈕、
選單或其他 LINE 介面文字，並可能有重疊或缺少尚未載入、未對外公開的留言。
若程式讀不到留言但畫面可選取文字，可改用下方的複製文字方式。

## 保存已複製的文字

選取並複製記事本內容後，在終端機執行下列指令。

```sh
pbpaste | .venv/bin/python -m notesync capture-text -
```

若文字已另存成 UTF-8 檔，可用檔案路徑取代 `-`。
文字模式保留中文、換行與重複內容，接受最多 2 MiB 的 UTF-8 文字。

## 查看結果

指令回傳 `capture` 路徑。用文字編輯器開啟 `local-evidence/line-note-*.json`，
在 `evidence.elements` 查找介面文字，或在 `evidence.text` 查看複製內容。
每份檔案記錄擷取時間、手動指定的來源與方式。完整性預設為 `UNKNOWN`，
探針遇到讀取上限或元素失效時標為 `PARTIAL`。證據 JSON 與 [訂單匯入快照](DATA_CONTRACT.md)
是不同格式，需先逐筆核對及整理才能走既有的手動匯入流程。
`local-evidence/` 由 Git 忽略，適合保存本機對照檔。

擷取檔的 23 個文字元素是記事本標籤和清單控制項。接著打開顯示 19 則留言的貼文，
在兩個捲動位置以及按「查看之前的留言」載入後，比對畫面與輔助使用介面。
畫面可見作者和喊單文字，輔助使用介面未取得兩者。部分讀取遇到失效元素，

## 步驟與案例

1. 固定來源範圍與人工逐筆基準，跨至少兩個可視區域，宜達 30 筆；不足則記覆蓋缺口。
2. 比對作者標示、全文、多行邊界、順序、重複暱稱／內容、全形及可用的折疊回覆。
3. 記錄延遲載入與捲動前後結果；同總數不等於相同內容。
4. 改變捲動位置、關閉重開後再讀，分別檢查 comment/author ID；RuntimeId／位置不算穩定 ID。
5. 空篇也測；記錄未知、截斷與停止條件。
6. 記錄原人工整理、複製準備、匯入及核對耗時、異常比例，效益尚不可由 smoke 推定。

## 能力矩陣

| 能力 | YES／NO／UNKNOWN | 證據與限制 |
| --- | --- | --- |
| text_readable | NO | 本機所測的展開與載入方式均讀不到留言作者和正文 |

| completeness_detectable | UNKNOWN | 畫面總數無法用來驗證擷取檔的留言完整性 |

## 結論

本次所測版本、視窗與方法的結論為 `NOT_FEASIBLE`。其他版本與擷取方法需各自驗證。
可行性狀態定義如下。

- FEASIBLE：在記錄版本／範圍內取得完整快照；無穩定 ID 僅支援快照核對。
- NOT_FEASIBLE：所試方法／版本存在明確阻礙，不宣稱 UIA 永遠不可行。
- INCONCLUSIVE：1–2 工程日限時或基準不足仍無法判定，不等同通過。

缺頁、作者／全文不可讀、範圍不明或完整性未知即停止自動同步投入，沿手動核心繼續。
不自行擴大成 OCR、私人 API 或協定破解。模板存在不代表 S01 已完成。

## S08 前額外驗收

30 筆 smoke 不足以啟用排程。另需至少 100 筆或實際尖峰量較大者，包含延遲載入、
跨頁重疊、擷取中新增留言，兩次重讀一致或可核對的一致時間窗；每輪仍要當批證據。
多篇隔離、OPEN／LOCKED 與失敗不覆寫報表依 S08 驗收，不能由 S01 smoke 推定。
