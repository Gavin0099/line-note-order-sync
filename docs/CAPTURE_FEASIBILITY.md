# S01 擷取實驗記錄模板

狀態：`NOT_EVALUATED`。本檔是模板；未執行 LINE、UIA probe 或實際留言核對。
S00 只建立本模板，S01 才填入實測結果。

## 環境與範圍

| 欄位 | 實際值 |
| --- | --- |
| 測試日期／操作者 | 待實測 |
| OS／LINE 版本 | 待實測 |
| Python／UIA 套件／probe 版本或 commit | 待實測 |
| 來源種類 | 候選 line_openchat_note；本人確認後固定 |
| scope／note 的去識別代號 | 待實測 |

| 本機證據路徑、hash | 待實測；不提交原文／截圖／傾印 |

由本人登入並開啟有權讀取的文章；不擷取 Token、登入資料或私人 API。
先唯讀觀察元素與 text patterns，人工捲動／展開；如需程式操作，只限載入、捲動及展開。
不傳訊息、不編輯、刪除或改記事本；此實驗不寫正式訂單 DB。

## 步驟與案例

1. 固定來源範圍與人工逐筆基準，跨至少兩個可視區域，宜達 30 筆；不足則記覆蓋缺口。
2. 比對作者標示、全文、多行邊界、順序、重複暱稱／內容、全形及可用的折疊回覆。
3. 記錄延遲載入與捲動前後結果；同總數不等於相同內容。
4. 改變捲動位置、關閉重開後再讀，分別檢查 comment/author ID；RuntimeId／位置不算穩定 ID。
5. 空篇也測；記錄未知、截斷與停止條件。
6. 記錄原人工整理、複製準備、匯入及核對耗時、異常比例，效益尚不可由 smoke 推定。

## 結論

實驗結果尚未填寫。S01 執行後擇一，附實際步驟與證據：

- FEASIBLE：在記錄版本／範圍內取得完整快照；無穩定 ID 僅支援快照核對。
- NOT_FEASIBLE：所試方法／版本存在明確阻礙，不宣稱 UIA 永遠不可行。
- INCONCLUSIVE：1–2 工程日限時或基準不足仍無法判定，不等同通過。

缺頁、作者／全文不可讀、範圍不明或完整性未知即停止自動同步投入，沿手動核心繼續。
不自行擴大成 OCR、私人 API 或協定破解。模板存在不代表 S01 已完成。

## S08 前額外驗收

30 筆 smoke 不足以啟用排程。另需至少 100 筆或實際尖峰量較大者，包含延遲載入、
跨頁重疊、擷取中新增留言，兩次重讀一致或可核對的一致時間窗；每輪仍要當批證據。
多篇隔離、OPEN／LOCKED 與失敗不覆寫報表依 S08 驗收，不能由 S01 smoke 推定。
